# Capture and release integration (Issue #10)

`CaptureRoundCoordinator` and `CapturedPlayerState` are intentionally isolated under `Assets/Game/Capture/`. Add `CapturedPlayerState` to each network player prefab and `CaptureRoundCoordinator` to a spawned network object in the mission scene. The coordinator does not change shared player prefabs or mission scenes in this issue.

## Hooks for Issue #12

- **Host capture call:** after host-side AI detection, call `CaptureRoundCoordinator.Instance.TryCaptureServer(residentBrain, playerState)`. The method accepts only a chasing resident within its configured capture radius. Call it from the host's AI update/event path; never accept a client supplied chase state.
- **Drop/reset/event:** subscribe to `CapturedPlayerState.CaptureChanged` for player state changes and `CaptureRoundCoordinator.RoundLostChanged` for defeat UI. On mission restart call `ResetRoundServer()` on host; it clears all currently spawned players and the shared defeat state. Existing gift drop/reset remains owned by the mission integration.
- **Recovery:** a free local player's interaction calls `rescuerState.RequestRelease(targetState)`. The server derives sender identity from NGO RPC metadata and checks sender is free, target is captured, players differ, both are in range, and both player objects exist before releasing.
- **Initialization:** ensure the coordinator is spawned before enabling capture interactions. Player `NetworkVariable<bool>` starts false for a new network object, so late joiners initialize free; on disconnect the host recalculates defeat from remaining spawned player objects. Reset after defeat is host-only (R on host).

## Isolated smoke setup

Use the Capture test scene/prefab generated by `Tools/Capture/Build Capture Test Scene`. Start as host/client with `--host` / `--client`. For the multiplayer smoke, start two instances and exercise capture/release, then repeat with one connected player and with both players captured; verify the host restart resets state. Disconnect cleanup is checked by disconnecting a captured client. The real AI hook remains host-only and requires `ResidentBrain.State == Chasing` plus configured proximity.

## Capture test controls

The generated scene starts with a resident facing the host spawn. After its built-in sight hold elapses, it chases and the host test adapter captures players that enter the contact radius. Move the client with WASD near a captured teammate and press E to request release. When every connected player is captured, the host sees the defeat prompt and presses R to restart. Repeat with only one client connected for the solo case. The adapter exists only in this test scene/prefab.
