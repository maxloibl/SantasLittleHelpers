# Capture and release integration (Issue #10)

`CaptureRoundCoordinator` and `CapturedPlayerState` are intentionally isolated under `Assets/Game/Capture/`. Add `CapturedPlayerState` to each network player prefab and `CaptureRoundCoordinator` to a spawned network object in the mission scene. The coordinator does not change shared player prefabs or mission scenes in this issue.

## Hooks for Issue #12

- **Host capture call:** after host-side AI detection, call `CaptureRoundCoordinator.Instance.TryCaptureServer(residentBrain, playerState)`. The method accepts only a chasing resident within its configured capture radius. Call it from the host's AI update/event path; never accept a client supplied chase state.
- **Drop/reset/event:** subscribe to `CapturedPlayerState.CaptureChanged` for player state changes and `CaptureRoundCoordinator.RoundLostChanged` for defeat UI. On mission restart call `ResetRoundServer()` on host; it clears all currently spawned players, resets residents and clears shared defeat state. Existing gift drop/reset remains owned by mission integration.
- **Recovery:** a free local player's interaction calls `rescuerState.RequestRelease(targetState)`. The server derives sender identity from NGO RPC metadata and checks sender is free, target is captured, players differ, both are in range, and both player objects exist before releasing.
- **Initialization:** ensure the coordinator is spawned before enabling capture interactions. Player `NetworkVariable<bool>` starts false for a new network object, so late joiners initialize free; on disconnect the host recalculates defeat from remaining spawned player objects. Reset after defeat is host-only (R on host).

## Isolated smoke setup

Use the Capture test scene/prefab generated by `Tools/Capture/Build Capture Test Scene`. Its transport uses port 7780. `Tools/Capture/Build Windows Smoke Player` writes to `Builds/CaptureSmoke/CaptureSmoke.exe`. Launch hidden host/client instances with `--batchmode -nographics --host` and `--batchmode -nographics --client`.

For solo loss/reset, start the host with `--capture-auto-reset`. For all-captured reset, start both instances with host `--capture-auto-reset --capture-wait-for-client`, client `--client`. For partner release, start host with `--capture-rescue-smoke --capture-wait-for-client` and client with `--capture-auto-rescue`. Add `--shutdown-after=12` to stop an instance normally. Logs include `CAPTURE_HOST_CAPTURE`, `CAPTURE_HOST_RELEASE`, `CAPTURE_ROUND_LOST`, `CAPTURE_HOST_RESET`, and `CAPTURE_NET_DISCONNECTED`. The production capture hook remains host-only and requires `ResidentBrain.State == Chasing` plus configured proximity.
